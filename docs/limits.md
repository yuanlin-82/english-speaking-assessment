# Limits and non-claims

1. **Not a vendor replacement** — pronunciation-accuracy / content-completeness internals stay with the speech provider unless separately rebuilt and validated.
2. **Not content depth / complexity under auto-scoring** — the report axis is **coverage** of task demand; examiner-style depth remains largely human in large oral exams ([content-completeness.md](content-completeness.md)).
3. **Not a CEFR or branded speaking-exam instrument** — mentioning well-known exams as *examples* of elicitation families is not a claim to implement those exams or their band scales.
4. **Not interaction-based oral proficiency as shipped** — adaptive examiner / strategy libraries, if any, are design territory; this repo’s measurement path is task-based.
5. **Not English-medium competency interviewing** — job-evidence follow-ups in English belong with [ai-interview-decision-map](https://github.com/yuanlin-82/ai-interview-decision-map), not oral ability scores here.
6. **Not production config** — weights, prompts, audio, RMSE tables, and lexicons stay private ([NOTICE.md](../NOTICE.md)).
7. **Fluency is hard on short speech** — composition and UI should expose uncertainty, not fake precision.
8. **Expert alignment is ongoing** — “self-built fluency” implies a validation burden; publishing the chain is not the same as publishing a frozen model.
